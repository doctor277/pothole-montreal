# Security Policy

## Reporting a vulnerability

Please use GitHub's private vulnerability reporting feature under **Security → Advisories → Report a vulnerability** when it is available for this repository. If private reporting is not enabled, open a minimal issue asking the maintainer to enable a private reporting channel; do not include exploit details, credentials, private user data, or sensitive infrastructure information in a public issue.

Include the affected component, impact, reproduction prerequisites, and a concise remediation suggestion. Redact tokens, signed URLs, personal data, private photos, and other secrets from every report and attachment.

## Testing boundaries

Do not test vulnerabilities against hosted development or production infrastructure, user accounts, private Storage objects, or third-party services without explicit written authorization. Use a local environment and synthetic data.

Do not attempt denial of service, credential attacks, automated account creation, bulk anonymous submissions, paid AI requests, or access to citizen/admin data.

## Scope note

This is a development-stage portfolio project, not an official City of Montréal service. A public source repository does not authorize testing of any separately hosted infrastructure.
